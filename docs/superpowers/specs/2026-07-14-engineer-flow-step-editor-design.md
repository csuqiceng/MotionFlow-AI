# 工程师流程步骤编辑与执行时间线设计

## 目标

在现有 Web 工程师命令库和流程库基础上，补足旧版 Qt 中最常用的流程编排体验：不输入 JSON 即可维护步骤顺序，并在真实运行时看到每一步的状态。

## 范围

本阶段只实现以下能力：

- 在流程草稿中拖拽调整步骤顺序；
- 复制一个步骤到其原步骤之后；
- 删除步骤；
- 执行命令或流程时，以时间线显示等待、执行中、完成或失败；
- 某一步失败时，终止后续步骤并展示失败原因。

条件分支、循环、重试策略、导入导出和版本回滚不属于本阶段。

## 交互

采用三栏布局：

1. 左栏为命令与流程库，用于选择当前编辑项；
2. 中栏为流程步骤，提供“添加命令步骤”、拖动手柄、复制、删除、保存和发布；
3. 右栏为最近一次执行的时间线及“检查并执行”入口。

拖拽结束时立即在本地草稿中重排，用户点击保存后再持久化。复制会深拷贝步骤参数和覆盖项，生成一个新的步骤标识。删除必须保留至少零个步骤的合法草稿状态。

## 数据与执行

前端以稳定的步骤标识维护顺序；重排、复制和删除复用现有流程草稿更新接口。执行仍走既有预检、权限和自动执行策略，不能绕过控制器安全检查。

执行状态为 `queued`、`running`、`succeeded`、`failed`、`skipped`。流程开始时每一步为 `queued`；当前步骤为 `running`；成功后为 `succeeded`；失败步骤保存服务端错误信息，剩余步骤标为 `skipped`。命令执行以单步骤时间线显示。

## 错误处理

- 空流程不可执行，并在编辑器中解释原因；
- 预检失败时不开始执行，时间线显示预检失败信息；
- 网络或服务端错误保留已获得的步骤状态，并显示可读错误；
- 保存、发布、执行期间禁用冲突操作，避免覆盖草稿。

## 验证

测试先行覆盖：拖拽重排结果、复制参数独立性、删除、成功执行的时间线、单步失败后续跳过。完成后执行相关单元测试、全量前端构建，并在 `127.0.0.1:5173` 实际登录工程师页面验证编辑入口；不从自动化测试触发真实机械手动作。
